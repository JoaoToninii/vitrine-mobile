3 3. Instale o Expo Router e suas dependências
Como no encontro 4, use npx expo install: ele escolhe a versão de cada pacote compatível com o SDK 57.
São cinco pacotes, divididos em dois comandos só para caber na linha.
n expo-router — o roteador: lê a pasta app/ e transforma cada arquivo em tela.
n react-native-screens — faz cada tela da pilha virar uma tela nativa de verdade, e não uma View
desenhada por cima da outra.
n expo-linking — traduz endereços como vitrine://produto/3 em navegação. É ele que torna o deep link
possível.
n expo-constants — deixa o roteador ler o app.json enquanto o aplicativo roda; é de lá que ele tira o scheme.
n @expo/vector-icons — os ícones das abas. No SDK 57 ele deixou de vir dentro do pacote expo, e precisa
ser instalado.

7 7. Guarde as cores da navegação no tema.ts
O cabeçalho do topo e a barra de abas não são componentes seus: quem os desenha é o Expo Router, e você
só descreve como devem ficar, num objeto de opções. Esse objeto recebe cor como valor, não className —
as classes dark: não chegam lá. Por isso as cores da navegação precisam existir em TypeScript, uma vez para
cada tema.
n As chaves light e dark têm o mesmo nome dos valores que o useColorScheme devolve. Escolher a paleta
vira uma consulta: CORES_NAVEGACAO['dark'] devolve as cinco cores do escuro.
n As cores do claro são as mesmas das classes do encontro 4, escritas em hexadecimal: branco no fundo,
slate-900 (#0F172A) no texto, sky-700 (#0369A1) no destaque.
n O escuro reaproveita o CORES, que existe desde o encontro 2. Mudou a paleta? Muda num lugar só.
n as const torna o objeto somente leitura, e faz o editor completar cores.fundo, cores.texto enquanto você
digita.

const CATEGORIAS = ['todas', 'beauty', 'fragrances', 'furniture'];
export default function CatalogoScreen() {
const router = useRouter();
const [categoria, setCategoria] = useState('todas');
const [favoritos, setFavoritos] = useState<number[]>([]);
const visiveis =
categoria === 'todas'
? PRODUTOS
: PRODUTOS.filter((p) => p.category === categoria);
function alternarFavorito(id: number) {
setFavoritos((atuais) =>
atuais.includes(id)
? atuais.filter((f) => f !== id)
: [...atuais, id]
);

categorias={CATEGORIAS}
selecionada={categoria}
aoSelecionar={setCategoria}

visiveis.map((produto) => (

7. Por que a navegação não usa className
As telas continuam pintadas com classes, mas o cabeçalho e a barra de abas receberam cores escritas à mão.
Não é descuido: eles não são componentes seus.
n Quem desenha a barra de abas é o Expo Router. Você só descreve como ela deve ficar, em
screenOptions, e esse objeto aceita cor como valor, não como classe.
n Como o prefixo dark: não chega lá, o tema vira uma consulta: o useColorScheme diz qual tema está ativo,
e o CORES_NAVEGACAO devolve as cores daquele tema.
n Quando o tema muda, o layout redesenha e a consulta é refeita — o mesmo ciclo de estado do encontro 3,
agora para a navegação.
n O useEffect do layout raiz cuida de um detalhe do navegador: na abertura, o hook já sabe o tema do
sistema, mas as classes dark: só ligam quando alguém chama setColorScheme. A linha confirma o tema
uma vez, e a tela e a barra começam da mesma cor.
dois jeitos de pintar, lado a lado
// a tela é sua: className funciona
<View className="flex-1 bg-white dark:bg-fundo" />
// a barra de abas é do Expo Router: ela recebe
// um objeto de opções, e não um componente com className
<Tabs screenOptions={{
tabBarStyle: { backgroundColor: cores.fundo },
}} />
// por isso a cor vem de uma consulta ao tema atual
const cores = CORES_NAVEGACAO[colorScheme === 'dark' ? 'dark' : 'light'];
EM UMA FRASE
Nas suas telas, classe. Nas peças do Expo Router, objeto de opções com as cores do tema atual.
