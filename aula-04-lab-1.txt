3 3. Instale as três bibliotecas
Use npx expo install, e não npm install: o Expo consulta o SDK 57 e escolhe a versão compatível de cada
pacote. O npm install traria a mais recente, que nem sempre é a certa para este SDK.
n nativewind — o tradutor. Converte as classes em objetos de estilo do React Native durante a compilação.
n tailwindcss — o dono das classes: a escala de espaçamento, a paleta padrão e o arquivo de configuração
são dele. Precisa ser a versão 3, porque o NativeWind 4 ainda não acompanha a 4.
n react-native-reanimated — exigido pelo NativeWind para animar transições de classe. Você não vai
escrever animação hoje, mas sem ele a biblioteca não carrega.
Terminal
npx expo install nativewind tailwindcss react-native-reanimated
Confira: Abra o package.json e confirme as três em dependencies. O tailwindcss precisa estar em ^3.4; se
aparecer 4.x, rode npm install tailwindcss@^3.4.
4 4. Instale também o babel-preset-expo
Este passo não está na documentação do NativeWind, e é o que mais trava o laboratório. O SDK 57 não deixa
o babel-preset-expo na raiz do node_modules: ele fica dentro de node_modules/expo/node_modules.
Enquanto ninguém escreve um babel.config.js isso não faz diferença, porque quem usa o preset é o próprio
Expo, que sabe onde ele está. No passo 8 você escreve esse arquivo, e o Babel passa a procurar o preset a
partir da raiz do projeto — onde ele não está.
Terminal
npx expo install babel-preset-expo --dev
Confira: A pasta node_modules/babel-preset-expo passa a existir e o pacote aparece em devDependencies
no package.json.
Atenção: Pulando este passo, o erro só aparece no passo 12, assim: Cannot find module
'babel-preset-expo', seguido de Cannot read properties of undefined (reading
'transformFile'). O Metro nem chega a empacotar, e a mensagem não cita o NativeWind — por isso quase
todo mundo procura no lugar errado.
5 5. Gere o arquivo de configuração do Tailwind
O comando cria um tailwind.config.js mínimo na raiz. Ele existe no Tailwind 3 e foi removido no 4 — mais um
motivo para o projeto ficar na versão 3.
Terminal
npx tailwindcss init
Confira: A resposta é Created Tailwind CSS config file: tailwind.config.js, e o arquivo aparece na raiz, ao lado
do package.json.

6 6. Declare a paleta da Vitrine como tokens
Substitua o conteúdo inteiro do arquivo. Aqui você faz, em escala pequena, o trabalho de tokens do UI
Engineer: as cores deixam de ser valores soltos espalhados pelo código e viram nomes com significado. São
as mesmas cinco cores do src/constants/tema.ts — a diferença é que agora elas viram classe.
n content — a lista de arquivos que o Tailwind varre procurando classes. O que não está aqui não recebe
estilo.
n presets — carrega os padrões do NativeWind, que adaptam o Tailwind ao React Native: sem grid, sem
float, medidas em pontos.
n theme.extend — acrescenta à paleta padrão em vez de substituí-la. É por isso que você continua tendo
bg-slate-100 e text-white ao lado dos seus tokens.
n darkMode: 'class' — o tema deixa de vir apenas do sistema operacional e passa a ser controlável por
código. É o que torna possível o botão do passo 20.
n Cada token vira sufixo de classe: fundo gera bg-fundo, text-fundo e border-fundo; card gera rounded-card.
tailwind.config.js
/** @type {import('tailwindcss').Config} */
module.exports = {
darkMode: 'class',
content: ['./App.tsx', './src/**/*.{js,jsx,ts,tsx}'],
presets: [require('nativewind/preset')],
theme: {
extend: {
colors: {
fundo: '#0F1B33',
superficie: '#1D3B73',
destaque: '#61DAFB',
alerta: '#F0A500',
suave: '#CBD5E1',
},
borderRadius: {
card: '12px',
},
},
},
plugins: [],
};
Atenção: Se você criar componentes numa pasta fora de src/, precisa acrescentá-la em content. Classe em
arquivo não listado simplesmente não funciona, e sem mensagem de erro — é o sintoma mais confuso desta
aula.

7 7. Crie o arquivo CSS de entrada
Crie global.css na raiz do projeto, ao lado do package.json. É o único CSS que a Vitrine terá, e ele não vai
para o celular: serve para o NativeWind saber quais famílias de classe precisa gerar.
global.css
@tailwind base;
@tailwind components;
@tailwind utilities;
Confira: O arquivo tem exatamente três linhas e está na raiz — não dentro de src/.
Atenção: O VS Code sublinha @tailwind como regra desconhecida. É aviso do editor, não erro do projeto: a
extensão Tailwind CSS IntelliSense, instalada no encontro 1, faz o aviso sumir.
8 8. Configure o Babel
Crie babel.config.js na raiz. É este arquivo que habilita a prop className: o jsxImportSource manda o
compilador montar o JSX com a versão do NativeWind dos componentes, no lugar da versão original do React
Native.
babel.config.js
module.exports = function (api) {
api.cache(true);
return {
presets: [
['babel-preset-expo', { jsxImportSource: 'nativewind' }],
'nativewind/babel',
],
};
};
Confira: O arquivo existe na raiz. Ainda não há como testá-lo: isso é o passo 12.
Atenção: A ordem dos dois presets importa, e o api.cache(true) não é decoração — sem ele o Babel
reprocessa a configuração a cada arquivo, e o empacotamento fica lento a ponto de parecer travado.
9 9. Configure o Metro
Crie metro.config.js na raiz. O Metro é o empacotador: lê os seus arquivos e produz o pacote JavaScript que
vai para o celular. O withNativeWind envolve a configuração padrão do Expo e acrescenta o passo que lê o
global.css.
metro.config.js
const { getDefaultConfig } = require('expo/metro-config');
const { withNativeWind } = require('nativewind/metro');
const config = getDefaultConfig(__dirname);
module.exports = withNativeWind(config, { input: './global.css' });
Confira: Os quatro arquivos — tailwind.config.js, global.css, babel.config.js e metro.config.js — estão na
raiz, lado a lado com o package.json.

10 10. Ensine o TypeScript sobre className e sobre o CSS
Crie nativewind-env.d.ts na raiz. Ele resolve duas coisas de uma vez, e as duas linhas são necessárias.
n A primeira linha acrescenta a prop className aos tipos dos componentes do React Native. Sem ela, o
editor sublinha className em todo componente como propriedade inexistente.
n A segunda linha avisa o TypeScript de que importar um arquivo .css é legítimo. Sem ela, o import do
próximo passo derruba o npm run check com TS2882: Cannot find module or type
declarations for side-effect import of './global.css'.
n Um arquivo .d.ts é só de declarações: não vira código nenhum no aparelho, existe apenas para o
compilador.
nativewind-env.d.ts
/// <reference types="nativewind/types" />
declare module '*.css';
Confira: Depois de recarregar a janela do VS Code (Ctrl+Shift+P → Developer: Reload Window), className
deixa de aparecer sublinhado em vermelho.
11 11. Importe o CSS no ponto de entrada
O import do global.css precisa estar no App.tsx, de preferência na primeira linha. Repare que o
SafeAreaProvider continua envolvendo tudo: é ele que mede as bordas do aparelho, e é dele que o
SafeAreaView da tela tira essa medida. Removê-lo deixa a tela sem valor para consultar.
App.tsx
import './global.css';
import { StatusBar } from 'expo-status-bar';
import { SafeAreaProvider } from 'react-native-safe-area-context';
import { CatalogoScreen } from '@/screens/CatalogoScreen';
export default function App() {
return (
<SafeAreaProvider>
<CatalogoScreen />
<StatusBar style="light" />
</SafeAreaProvider>
);
}
Confira: Rode npm run check: precisa terminar limpo. Se acusar o TS2882, falta a segunda linha do arquivo do
passo 10.
Atenção: O import do CSS não tem chaves e não guarda nada em variável: é um import de efeito colateral, que
existe só para o empacotador saber que aquele arquivo faz parte do projeto.

14 14. Converta o CardProduto
Comece pelo componente mais rico, porque ele exercita quase toda a gramática de uma vez. Apague o arquivo
inteiro antes de colar a versão nova — inclusive a linha de import lá em cima, que muda. O resultado visual

n O import do StyleSheet sumiu, e o de CORES também: o cartão não consulta mais o tema.ts, porque as

16 16. Converta o FiltroCategorias e conserte o chip esticado
Este é o componente com as três armadilhas da aula. A primeira: o ScrollView não tem só a prop style — ele
tem também a contentContainerStyle, e cada uma vira uma classe diferente. A segunda e a terceira estão
nos tópicos, e as duas são defeitos que vêm do encontro 3: aproveite que está reescrevendo o arquivo para
corrigi-los.
n contentContainerClassName é a única prop de estilo com nome próprio. A regra do NativeWind é geral:
onde havia xStyle, passa a haver xClassName.
n items-start conserta o chip esticado. Num ScrollView horizontal o alinhamento padrão é stretch, então
cada chip crescia até a altura da faixa inteira — no encontro 3 eles ficavam alongados, e ninguém reparou
porque não havia com o que comparar.
n grow-0 conserta o vão embaixo dos chips: sem ele o ScrollView ocupa toda a altura que sobra, e a lista de
produtos é empurrada para baixo.
n O estilo condicional é uma string montada em JavaScript, com crases. Não há mágica: className aceita
qualquer string.
n Repare que não há mais arranjo de estilos. Onde havia style={'{'}[styles.chip, ativa && styles.chipAtivo]{'}'},
agora há uma classe ou a outra.

n O SafeAreaView vem de uma biblioteca de terceiros e mesmo assim aceita className — o NativeWind 4
já traz o suporte pronto para ela. Nem toda biblioteca tem, e as que não têm exigem um registro à parte.

src/screens/CatalogoScreen.tsx
import { useEffect, useState } from 'react';
import { ScrollView, Text, View } from 'react-native';
import { SafeAreaView } from 'react-native-safe-area-context';
import { Cabecalho } from '@/components/Cabecalho';
import { CardProduto } from '@/components/CardProduto';
import { FiltroCategorias } from '@/components/FiltroCategorias';
import { PRODUTOS } from '@/constants/produtos';
const CATEGORIAS = ['todas', 'beauty', 'fragrances', 'furniture'];
export function CatalogoScreen() {
const [categoria, setCategoria] = useState('todas');
const [favoritos, setFavoritos] = useState<number[]>([]);
const visiveis =
categoria === 'todas'
? PRODUTOS
: PRODUTOS.filter((p) => p.category === categoria);
function alternarFavorito(id: number) {
setFavoritos((atuais) =>
atuais.includes(id)
? atuais.filter((f) => f !== id)
: [...atuais, id]
);
}
useEffect(() => {
console.log('categoria selecionada:', categoria);
}, [categoria]);
return (
<SafeAreaView className="flex-1 bg-fundo">
<View className="flex-1 p-4">
<Cabecalho titulo="Vitrine" favoritos={favoritos.length} />
<FiltroCategorias
categorias={CATEGORIAS}
selecionada={categoria}
aoSelecionar={setCategoria}
/>
<ScrollView className="mt-4" showsVerticalScrollIndicator={false}>
{visiveis.length === 0 ? (
<Text className="text-suave text-center mt-10">
Nenhum produto nesta categoria.
</Text>
) : (
visiveis.map((produto) => (
<CardProduto
key={produto.id}
produto={produto}
favorito={favoritos.includes(produto.id)}
aoAlternarFavorito={alternarFavorito}
/>
))
)}
</ScrollView>
</View>
</SafeAreaView>
);
}

19 19. Entenda a regra do tema claro antes de escrever
Até agora a Vitrine só existe em escuro. O prefixo dark: aplica a classe apenas no tema escuro; a classe sem
prefixo vale no claro. Uma linha resolve os dois. Os três passos seguintes fazem isso arquivo por arquivo, e a
regra é sempre a mesma:
n O par se escreve claro primeiro, escuro depois: bg-white dark:bg-fundo lê-se "branco, e azul-escuro no
tema escuro".
n Só precisa de prefixo o que muda entre os temas. Tamanho, espaçamento, raio e alinhamento continuam
sem ele — escrever dark: em tudo é desperdício e polui a linha.
n O ponto de atenção é o contraste. O ciano #61DAFB é ótimo sobre azul-escuro e ilegível sobre branco: o

4. A gramática de uma classe
Toda classe do Tailwind segue o mesmo desenho, e reconhecer as quatro partes economiza muita ida à
documentação. Leia a tabela com o CardProduto aberto ao lado.
No código O que significa
p-4 Propriedade e valor. A letra é a propriedade (p de padding), o
número é o passo da escala. Como a escala é de 4 em 4, p-4
vale 16.
px-4 py-2.5 Eixo. O x é horizontal e o y é vertical. O passo aceita meio:
py-2.5 vale 10.
text-[15px] Valor arbitrário. Os colchetes escapam da escala quando o valor
que você precisa não está nela. Use com parcimônia: cada
colchete é uma exceção ao sistema.
bg-superficie Token seu. Nasceu em theme.extend.colors. O prefixo diz onde
aplicar (bg, text, border) e o sufixo é o nome que você deu.
dark:bg-fundo Modificador. O que vem antes dos dois-pontos é a condição.
Sem condição, a classe vale sempre.
active:opacity-60 Modificador de estado. Vale enquanto o dedo pressiona. É o
equivalente móvel do hover: da web.
flex-1 Layout. O mesmo flex: 1 do encontro 3: ocupe o espaço que
sobrar no eixo principal.

Propriedade, eixo, valor e modificador. Toda classe que você escreveu hoje cabe nessas quatro peças.

preferência do sistema; o do nativewind também escreve. Importar do lugar errado compila e não funciona.
n A decisão escondida é o darkMode: 'class'. Com ele, o dono do tema é o seu código. Sem ele, é o sistema
operacional, e o botão não tem o que trocar.
n O tema escolhido não sobrevive ao fechamento do aplicativo: ele vive em memória. Guardá-lo é assunto
do encontro 12, com AsyncStorage.
