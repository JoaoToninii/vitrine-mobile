2 Gere uma lista grande para o problema aparecer
CONCEITO — Problema de escala
Boa parte dos defeitos de desempenho é invisível com dado de exemplo e só aparece com dado real. Um
catálogo de loja tem centenas de itens, então vamos fabricar 500 a partir dos quatro que já existem. Os
dados não precisam ser bonitos: precisam ser muitos e ter ids únicos, porque é o id que identifica cada
item daqui em diante.
Crie a pasta src/utils e, dentro dela, o arquivo abaixo.
src/utils/gerarProdutos.ts
import { PRODUTOS } from '@/constants/produtos';
import { Produto } from '@/types/produto';
/** Repete a base de exemplo até atingir a quantidade pedida. */
export function gerarProdutos(quantidade: number): Produto[] {
const lista: Produto[] = [];
for (let i = 0; i < quantidade; i += 1) {
const base = PRODUTOS[i % PRODUTOS.length];
lista.push({
...base,
id: i + 1,
title: `${base.title} #${i + 1}`,
});
}
return lista;
}
// Gerada uma única vez, quando o arquivo é carregado. O catálogo e o
// detalhe importam esta mesma constante e enxergam os mesmos produtos.
export const PRODUTOS_TESTE = gerarProdutos(500);
No código O que significa
i % PRODUTOS.length Resto da divisão. Com quatro produtos, dá 0, 1, 2, 3, 0, 1, 2, 3...
e percorre a base em círculo.
{ ...base, id: i + 1 } Espalhamento. Copia todos os campos de base e depois
sobrescreve o id. O campo escrito por último vence.
`${base.title} #${i + 1}` Template string. Põe o número no título, para você distinguir os
itens na tela: “Chanel Coco Noir #7”.
export const PRODUTOS_TESTE Constante de módulo. O que está fora de funções roda uma
única vez, quando o arquivo é importado pela primeira vez. Todo
mundo que importa recebe o mesmo arranjo.
Entenda o que você escreveu
n Por que o id é i + 1, e não o id da base? Se os 500 itens repetissem os ids 1 a 4, haveria 125 produtos com
id 1. O React usa o id para saber quem é quem, como você vai ver no passo 13.

6 Crie os componentes de estado
CONCEITO — Os quatro estados de uma tela com dados
Toda tela que depende de dados passa por quatro situações: carregando (os dados ainda não chegaram),
vazio (chegaram e não há nada), erro (não chegaram) e sucesso (a lista). Quase todo aplicativo iniciante
trata só o sucesso, e o usuário fica olhando uma tela em branco sem saber se deve esperar, desistir ou
tentar de novo.
Vazio e carregando parecem iguais, mas dizem coisas opostas: um diz não há nada, o outro diz espere.
Tratar os três é critério de correção do projeto final.
Crie os três num arquivo só, para que todas as telas do aplicativo mostrem essas situações do mesmo jeito.

7 Memorize o cartão
CONCEITO — React.memo
Por padrão, quando um componente renderiza, todos os filhos renderizam junto. Foi o que você mediu
no passo 4. O memo muda isso: antes de chamar o componente, o React compara cada prop nova com a
anterior e, se todas forem iguais, reaproveita o desenho que já tinha.
A comparação funciona como um ===. Números, textos e booleanos são comparados pelo valor; objetos e
funções, pela referência, o endereço na memória. Duas funções com o mesmo código, criadas em
renderizações diferentes, são diferentes para o memo. Guarde isso, porque é o motivo do passo 8.
Substitua o arquivo inteiro. O console.log do passo 4 continua, agora dentro da versão nova.

8 Converta o catálogo para FlatList
CONCEITO — Virtualização
A FlatList não desenha a lista inteira. Ela desenha só o que cabe na tela mais uma margem acima e
abaixo, a janela. Ao rolar, os itens que saem da janela são desmontados e os que entram são montados. A
memória fica praticamente constante, com 50 ou com 50 mil itens. É o mesmo princípio do RecyclerView do
Android e do UITableView do iOS.
Para isso, ela pede três coisas: o arranjo (data), uma função que desenha um item (renderItem) e uma
chave estável por item (keyExtractor). Em troca, também cuida do cabeçalho, da mensagem de lista vazia
e do espaço entre os itens.
Esta é a peça central do laboratório. Substitua o arquivo inteiro.

n useMemo em visiveis: o filtro só roda de novo quando a categoria muda. Favoritar não refaz o filtro dos 500
itens, e o arranjo continua sendo o mesmo objeto, então a FlatList percebe que os dados não mudaram.

funções, e o memo do passo 7 finalmente tem props iguais para comparar.

os itens da janela. Não tem problema: o memo de cada cartão compara as props, e só redesenha o cartão

CONCEITO — async, await e finally
Puxar a lista para baixo é o gesto universal de “buscar de novo”. A FlatList já sabe desenhá-lo: basta dizer
se ela está atualizando (refreshing) e o que fazer quando o usuário puxa (onRefresh).

13 Provoque o erro da chave
CONCEITO — A chave diz quem é quem

outro (desmonta um e monta outro). Quem decide é a chave. Com o id, a chave acompanha o produto.

seja qual for o produto que esteja ali.

animação. O favorito não serve para o teste, porque mora no pai, guardado pelo id. Por isso, por alguns
minutos, você vai dar ao cartão um estado próprio.

3. Igual no valor, diferente na referência
O memo compara cada prop como um ===. A tabela mostra por que funções e objetos criados dentro do
componente quebram essa comparação.
No código O que significa
1 === 1 true. Primitivos (número, texto, booleano) comparam o valor.
{} === {} false. Cada { } cria um objeto novo, em outro endereço, mesmo
vazio.
[1] === [1] false. Arranjos também são objetos.
(() => 1) === (() => 1) false. Cada função escrita é uma função nova, mesmo com o
código idêntico.
useCallback(fn, []) Devolve a mesma função enquanto as dependências não
mudam.
useMemo(() => v, [dep]) Devolve o mesmo resultado enquanto dep não muda.
EM UMA FRASE
Função ou objeto criado dentro do componente só passa na comparação do memo se vier de um
useCallback ou de um useMemo.
4. A chave: posição ou identidade
No passo 13, a borda vermelha ficou presa à posição, e não ao produto. O React reaproveita um componente
quando a chave se repete e descarta quando ela some.
n Chave pelo id: o estado local acompanha o produto. Se o produto sai da lista, o componente é desmontado
e o estado vai junto.
n Chave pelo índice: o estado fica preso à posição. Filtrar, ordenar ou inserir no começo põe outro produto
naquele lugar, com o estado do anterior.
n Estado que precisa sobreviver (como o favorito) mora no pai, guardado pelo id. É por isso que ele nunca
errou.
EM UMA FRASE
A chave é a identidade do item para o React: use o que identifica o dado, nunca o lugar que ele ocupa.
5. As regras dos hooks e o return antecipado
O React não sabe o nome dos seus hooks: ele os reconhece pela ordem em que são chamados, renderização
após renderização. Um return antes de um hook faz essa ordem mudar.
o erro e o acerto
// ERRADO: quando carregando é true, o useCallback não roda,
// e a ordem dos hooks muda de uma renderização para outra
if (carregando) return <Carregando />;
const atualizar = useCallback(async () => { /* ... */ }, []);
// CERTO: todos os hooks primeiro, os returns depois
const atualizar = useCallback(async () => { /* ... */ }, []);
if (carregando) return <Carregando />;

6. Quando usar memo, useCallback e useMemo
n memo: em item de lista longa e em componente caro que recebe as mesmas props com frequência. Não
em tudo, porque a comparação também custa.
n useCallback: em função passada para um componente memorizado ou usada como dependência de outro
hook. Fora desses casos, não ajuda.
n useMemo: em cálculo caro, como filtrar e ordenar centenas de itens. Somar dois números não justifica.
n Dependência esquecida congela o valor: o hook devolve o resultado velho para sempre. É pior do que não
memorizar.
n Meça antes e depois. Se o número não mudou, desfaça: memoização é complexidade a mais para ler e
manter.
